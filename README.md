# تکنو یدک - کنترل فاکتور و جمع‌آوری v24

این نسخه OCR را از طریق Backend رندر اجرا می‌کند و بانک محصولات ۱۸۶۴ کد از فایل «لیست محصولات.xlsx» داخل برنامه قرار گرفته است.

## استقرار
فایل‌های این پوشه را در همان GitHub repository قبلی جایگزین کنید و Commit کنید. Render خودش Deploy می‌کند.

Environment Variable:
- OCR_API_KEY = کلید فعلی OCR.space

## تغییر اصلی نسخه ۲۴
- کدهای محصول از کدهای دقیق موجود در بانک محصولات شناسایی می‌شوند، حتی اگر OCR عنوان ستون «کد کالا یا خدمات» را جدا از کدها استخراج کرده باشد.
- برای تعداد، از مختصات کلمه‌های OCR در ستون مقدار استفاده می‌شود؛ تعدادها فقط وقتی خودکار ثبت می‌شوند که همه ردیف‌ها مقدار معتبر داشته باشند و در صورت وجود «مقدار کل»، جمع تعدادها با آن برابر باشد.
- اگر تطبیق کامل برقرار نباشد، تعدادها خالی می‌مانند تا کاربر دستی تأیید کند؛ برنامه نباید قیمت یا عدد توضیحات را به‌جای تعداد حدس بزند.

## قابلیت این نسخه
- آپلود/عکس فاکتور از گوشی
- فشرده‌سازی عکس در مرورگر قبل از ارسال
- OCR فارسی از طریق Backend
- تشخیص فقط کدهایی که در بانک واقعی محصولات وجود دارند
- حذف شماره تلفن، تاریخ، مبلغ، شماره حساب و سایر اعداد نامرتبط از فهرست کالا
- تشخیص کدهای معتبر از بخش جدول فاکتور و استخراج تعداد از موقعیت ستون مقدار در overlay OCR
- کنترل جمع تعدادها با «مقدار کل» فاکتور، در صورت تشخیص این مقدار
- نمایش هشدار برای مواردی که تعداد از OCR با اطمینان کافی قابل تشخیص نیست
- امکان اصلاح دستی تعداد هر ردیف
- ذخیره و نمایش فاکتور آماده جمع‌آوری

## آزمایش انجام‌شده و محدودیت
- بررسی نحو JavaScript مرورگر و Node انجام شده است.
- منطق استخراج با داده آزمایشی ساختگی برای ۸ ردیف (۱۰، ۲۰، ۲۰، ۲۰، ۲۰، ۲۰، ۲۰، ۱۰؛ جمع ۱۴۰) تست شده است.
- این تست، اجرای زنده روی سرویس Render یا OCR واقعی همین فاکتور نیست. پس از استقرار باید همین فاکتور واقعی دوباره آزمایش شود. اگر مختصات OCR کافی نباشد، تعدادها عمداً خالی می‌مانند تا از ثبت مقدار اشتباه جلوگیری شود.


## اصلاحات نسخه ۲۴
- فقط کدهای صریح یا کدهای ابتدای ردیف از متن استخراج می‌شوند؛ عددهای داخل شرح کالا (مانند ۱۳۱ در «پراید ۱۳۱») به ردیف مستقل تبدیل نمی‌شوند.
- اگر OCR جایگاه هندسی تعداد را درست ندهد، بلوک متنی ستون مقدار به‌عنوان مسیر جایگزین بررسی می‌شود.
- مسیر جایگزین، سرستون مقدار داخل جدول اقلام را به‌جای مقدار کل فاکتور انتخاب می‌کند و اعداد قیمت دارای جداکننده هزارگان را به تعداد جعلی تبدیل نمی‌کند.
- اگر تعدادها با تعداد ردیف‌ها و جمع کل قابل تطبیق نباشند، خالی می‌مانند تا دستی تأیید شوند.

- مسیر جایگزین دوم، در خروجی‌هایی که OCR بلوک تعداد را قبل از بلوک قیمت می‌آورد، فقط آخرین دنباله تعدادهای کوچک را در صورت تطبیق دقیق با جمع کل می‌پذیرد.
