# کنترل سفارش تکنو یدک — نسخه ۳۲ (آزمون واردکردن اکسل)

## رفع اشکال ورود مستقیم اکسل
- فایل XLS/XLSX به مسیر جداگانه `/api/import-invoice` می‌رود و OCR روی فایل اکسل اجرا نمی‌شود.
- شماره فاکتور و نام مشتری در هر بار ورود از خروجی همان فایل جایگزین می‌شوند؛ مقدارهای قدیمی از فاکتور قبلی باقی نمی‌مانند.
- اگر نام مشتری پیدا نشود یا جمع مقدارها با مقدار کل برگه برابر نباشد، هشدار در صفحه نشان داده می‌شود.
- اگر واردکردن فایل خطا بخورد، ردیف‌های فاکتور قبلی پاک می‌شوند تا به‌اشتباه ارسال نشوند.
- ساختار جدول با هدر دوخطی «کد کالا یا / خدمات» و سلول‌های ادغام‌شده آزمایش شده است.

## انتشار
محتویات ZIP را در ریشه مخزن `yaser1700/techno-yadak-ocr` جایگزین کنید و Commit بزنید؛ Render باید نسخه تازه را Deploy کند. وابستگی‌ها طبق `package.json` نصب می‌شوند و `OCR_API_KEY` فقط باید در تنظیمات Render قرار بگیرد.

## آزمون‌های انجام‌شده محلی
- فایل XLS واقعی به XLSX تبدیل و سطرهای واقعی آن به آزمون تجزیه‌گر داده شد.
- نتیجه آزمون: شماره فاکتور و تاریخ استخراج شدند؛ نام خریدار استخراج شد؛ ۳ ردیف کالا با کدها و تعدادهای درست شناسایی شد؛ جمع ردیف‌ها ۱۲۰ و با «مقدار کل» برابر بود.
- `node --check server.js` و `node --check invoice-import.js` موفق بودند.
- هر پنج بلوک JavaScript صفحه از نظر نحو بررسی شدند.
- یک آزمون مرورگر با شبیه‌سازی API برای کنترل ادغام رابط انجام می‌شود؛ این آزمون جایگزین آزمون نهایی روی Render نیست.

## محدودیت‌های شناخته‌شده
آزمون‌های بالا ورود/تجزیه فاکتور نمونه را در محیط محلی بررسی می‌کنند؛ هنوز اجرای زنده روی Render و دوربین گوشی بررسی نشده‌اند. مأموریت‌ها در حافظه سرور نگهداری می‌شوند و در راه‌اندازی مجدد سرور ممکن است از بین بروند؛ برای استفاده پایدار، افزودن پایگاه‌داده لازم است.
